# Планирование
## Перечень автоматизируемых сценариев

- Позитивные сценарии
  - Покупка через платежный сервис
    - Все поля заполнены валидными данными (карта со статусом: _одобрена_) 
    - _Ожидаемый результат_: Операция одобрена банком
  - Покупка через кредитный сервис
    - Все поля заполнены валидными данными (карта со статусом: _одобрена_) 
    - _Ожидаемый результат_: Операция одобрена банком
- Негативные сценарии
  - Покупка через платежный сервис 
    - Все поля заполнены валидными данными (карта со статусом: _отклонена_) 
      - _Ожидаемый результат_: Операция отклонена банком
    - Введен номер из 16 цифр несохраненной карты
      - _Ожидаемый результат_: Операция отклонена банком  
  - Покупка через кредитный сервис
    - Все поля заполнены валидными данными (карта со статусом: _отклонена_) 
      - _Ожидаемый результат_: Операция отклонена банком
    - Введен номер из 16 цифр несохраненной карты
      - _Ожидаемый результат_: Операция отклонена банком  
  - Поле "Номер карты" заполнено неверно
    - Поле не заполнено
      - _Ожидаемый результат_: Поле должно быть заполнено
    - Введено 15 цифр
      - _Ожидаемый результат_: Неверный формат ввода
    - Попытка ввода более 16 цифр
      - _Ожидаемый результат_: Плейсхолдер принимает первые 16 цифр (срабатывает валидация)
    - Введены цифры и буквы
      - _Ожидаемый результат_: Неверный формат ввода
    - Введены буквы
      - _Ожидаемый результат_: Неверный формат ввода

  - Неверно указан срок действия карты
    - Неверно указан месяц
      - Поле не заполнено
        - _Ожидаемый результат_: Поле должно быть заполнено
      - Введен 00 месяц
        - _Ожидаемый резульатт_: Неверно указан срок действия карты
      - Введен 13 месяц
        - _Ожидаемый резульатт_: Неверно указан срок действия карты
      - Введен прошедший месяц текущего года 
        - _Ожидаемый результат_: Ошибка! Истек срок действия карты
    - Неверно указан год
      - Поле не заполнено 
        - _Ожидаемый результат_: Поле должно быть заполнено
      - Введен прошедший год
        - _Ожидаемый результат_: Ошибка! Истек срок действия карты
      - Введен год из далекого будущего (99)
        - _Ожидаемый резульатт_: Неверно указан срок действия карты
  - Наверно указан владелец
    - Поле не заполнено
      - _Ожидаемый результат_: Поле должно быть заполнено
    - Введены кириллические символы
      - _Ожидаемый результат_: Неверный формат ввода
    - Введены цифры
      - _Ожидаемый результат_: Неверный формат ввода
    - Введены цифры и буквы
      - _Ожидаемый результат_: Неверный формат ввода
    - Введены специальные символы
      - _Ожидаемый результат_: Неверный формат ввода
  - Введен неверный CVC/CVV
    - Поле не заполнено
      - _Ожидаемый результат_: Поле должно быть заполнено
    - Введено 2 цифры
      - _Ожидаемый результат_: Неверный формат ввода
    - Попытка ввода боле 3-х цифр
      - _Ожидаемый результат_: Плейсхолдер принимает первые 3 цифры (срабатывает валидация)
    - Введены цифры и буквы
      - _Ожидаемый результат_: Неверный формат ввода
    - Введены буквы
      - _Ожидаемый результат_: Неверный формат ввода

## Перечень используемых инструментов
- В качестве системы контроля версии проекта и хранения кода авто-тестов будет использоваться _Git_ и _GitHub_
  - Это удобный и многофункциональный инструмент
  - Является производственным стандартом в сфере IT
- Для написания авто-тестов и их запусков платформа _JUnit5_
  - Это наиболее широко используемая среда тестирования с развитой архитектурой
  - В его составе _JUnit Jupiter_, который включает необходимые расширения для написания тестов, а также все новые аннотации _junit_ и _TestEngine_
- Язык для написания авто-тестов _Java 11_
  - Это хорошо структурированный язык, со множеством встроенных классов
  - Имеет обширную поддержку вспомогательных библиотек
  - Является профильным языком на курсе 
- Система управления проектом _Gradle_
  - _Gradle_ является гибким инструментом, он не использует _XML_, поэтому во многом его конструкции выглядят короче
- Фреймворк _Selenide_ для управления браузером при выполнении авто-тестов
  - Он обеспечивает стабильность тестов и локаничный синтаксис
  - Включает автоматическое ожидание элементов (AJAX)
  - Удобные селекторы и встроенные скриншоты при падании тестов
- Систему контейнеризации _Docker_ для развертывания баз данных
  - Это удобная система преднастроенных контейнеров
  - Исключает необходимость запуска другой ОС
- Для генерации тестовых данных вспомогательный класс _Faker_
  - Он включает обширную библиотеку для генерации различных данных и их локализации
  - Исключает необходимость создавать собственный класс для генерации данных
- Для автоматического создания всех необходимых элементов датакласса _Lombok_
- Для взаимодействия с _SQL_ базами данных _JDBC_ и набор вспомогательных классов DbUnits
  - _JDBC_ является стандартной библиотекой java
  - DbUnits предоставляет различные удобства и делает взаимодействие с _JDBC_ проще
- Для формирования отчетов по результатам прогона тестов _Allure_
  - Удобные отчеты с классификацией дефектов
  - Интеграция с Selenide
  - Фиксация нужных событий в тестах
## Возможные риски при автоматизации
### Экономические
- Высокие затраты: Для небольшого сервиса оплаты затраты на инструменты автоматизации, инфраструктуру и обучения персонала могут быть неоправданы
- Трудозатратная поддержка: Незначительные изменения в интерфейсе или логике оплаты требуют их актуализации.
- Ограниченность тестов: Авто-тесты работают по строго заданным алгоритмам. Они не выявят визуальных багов или проблем с удобством использования.

### Технические
- Ложные срабатывания (Flaky tests): Нестабильность сетевых соединений с банковскими шлюзами может приводить к падению тестов без наличия реальной ошибки в коде
- Уязвимости в безопасности: Утечки авторизационных данных или токенов, если они жестко прописаны в скриптах или хранятся в незащищенных логах.
- Проблемы с тестовыми данными: Для систем оплаты критично наличие актуальных тестовых карт. Ошибки в подготовке этих данных или их повторное использование могут привести к сбоям в тестах.

## Интервальная оценка
- С учетом позитивных _HappyPath_ и негативных сценариев (ошибках в вводимых данных, отказа со стороны банка) на написание авто-тестов уйдет от 6 до 10 часов

## План сдачи работ
- Согласование плана с руководителем проекта
- Написание авто-тестов в течение 3-х дней с момента согласования плана
- Составление отчетов по результатам тестирование в течении 2-х дней
- Составление итогового отчета по результатам проделанных работ по автоматизации
